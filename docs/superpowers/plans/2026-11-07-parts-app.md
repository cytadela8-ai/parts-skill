# TME Parts App Implementation Plan

> **For agentic workers:** Implement only after the user approves the proposal. Use native
> task-by-task execution with review gates; no additional agent orchestration is required.

**Goal:** Replace the skill with a Python-controlled, browser-operated per-row sourcing app.

**Architecture:** Keep TME access and commercial checks deterministic. Two bounded typed agents
search and validate individual rows. A local Flask app persists jobs, revisions, human decisions,
evidence, and costs in a SQLite project directory.

**Tech Stack:** Python 3.13, uv, Flask, plain JavaScript, sqlite3, Decimal,
pydantic-ai-slim[openrouter], pytest, ruff, ty, uv_build.

**Spec:** [Approval proposal](../../parts-app-proposal.md).

## Global Constraints

- Do not implement before proposal approval; proposed interfaces below are subject to that gate.
- Retain every sourcing/review policy in the proposal; no automatic model upgrades or purchases.
- Absolute imports, 100-character lines, functions ≤100 lines, complexity ≤8, ≤5 positional args.
- Preserve existing local edits and BOM files. Use an isolated worktree for implementation.
- Resolve stable dependency versions again at implementation time; pin exact versions and lock.
- Run project commands with uv; no secrets in logs, model messages, version control, or exports.
- Run relevant tests, ruff check/format checks, and ty before claiming completion.

## Review Focus

- Importing AI output must preserve provenance instead of locking all selections as manual.
- Sorting/filtering and duplicate/grouped references must never redirect an action to another row.
- Manual edits during an in-flight response must win, with stale output retained only in history.
- Recovery/truncated search/API failures must not become false no-stock conclusions.
- Parallel requests, repairs, and unknown-charge timeouts must not bypass reserved spend limits.

## Proposed files and interfaces

Use `src/parts_app/` as the sole installed application package. Move useful old code; remove the
skill, skill metadata, old scripts, and sidecar workflow once parity is verified. Existing BOM
artifacts are user data and must not be deleted. No permanent legacy implementation or CLI shims.

| File | Responsibility |
| --- | --- |
| models.py | Typed BOM rows, requirements, candidates, verdicts, execution/review enums |
| csv_io.py | CSV import classification, column mapping, enriched/basket exports |
| store.py | SQLite transactions, row revisions, jobs, human decisions, cost reservations |
| tme.py | Auth, exact lookup, paginated search, batching, rate limiting, evidence cache |
| matching.py | Mappings, deterministic checks, quantities, Decimal prices, commercial ranking |
| agents.py | Typed row agents, allowed TME tools, structured output validation |
| prompts/search.md, prompts/validate.md | Versioned sourcing and evidence instructions |
| budget.py | Model metadata, preflight reservations, actual-cost reconciliation |
| procedures.py | Shared search/validation operations and publication rules |
| worker.py | Claims, bounded dispatch, pause/cancel/restart behavior |
| web.py, __main__.py | Flask routes, local launch CLI, dependency wiring |
| templates/, static/ | Upload, row selection, review, progress, cost display |
| data/footprint-translations.csv | Preserved mapping data with review/provenance metadata |
| tests/ | Behavior tests mirroring package responsibilities; fixtures contain no secrets |

Public contracts use keyword-only configuration when signatures would exceed parameter limits.
`ProjectId`, `RowId`, `RunId`, and `Revision` are explicit identifier types. All currency is Decimal.
`RowSnapshot` includes ID, revision, original fields, normalized requirements, selected symbol,
human review, and machine verdict. `RunLimits` contains provider/model, call/tool/token/USD limits.

The proposal is ready for scope/architecture approval. Implementation is intentionally pending.
Native execution is recommended: the workflows share transaction and budget contracts, and keeping
one implementation owner avoids unnecessary handoffs. This does not affect the app's row agents.
